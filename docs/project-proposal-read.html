UGREEN Hackathon 2026 · Round 1

Inbox Zero for NAS — Project Proposal

Track: Automate Your Workflow · Skill: inbox-zero-nas

1. What does your Skill do?

It clears an authorized NAS inbox by classifying files, proposing renames and folders, then applying confirmed moves and saving a Markdown digest.

2. Who is your target user, and what is their problem?

Freelancers and knowledge workers whose Downloads or inbox folders fill with invoices, contracts, receipts, screenshots, and zip dumps. Manual sorting is slow and error-prone; cloud organizers send private files off-device.

3. What is your solution?

inbox-zero-nas inventories one inbox, extracts document signals on the NAS, shows a preview plan, and only after confirmation renames, archives by category, optionally tags, and writes a digest—local-first Inbox Zero.

4. What is the main user flow?

User points at an inbox (or Downloads) → Skill lists up to 80 files → document extraction builds categories and names → user reviews the table → optional apply creates folders, renames, moves → digest saved under the archive root.

5. How is your idea different from existing tools or common AI solutions?

It is not a generic chat wrapper or cloud Drive sorter. It orchestrates UGOS file, document, and knowledge experts on private NAS storage, defaults to preview-only, never deletes, and keeps approvals on-platform.

6. Which UGREEN AI NAS features does your Skill use, and at which step?

file-agent inventory and Downloads resolve; document-agent extract for invoices/contracts/receipts; file-agent mkdir/rename/move and optional tags after confirm; knowledge-agent save-text for the digest.

7. What is your technical approach?

Markdown Skill with delegate-only orchestration. Evidence: ug-filesystem, ug-filemgr, file-workflow → file-agent; ug-document → document-agent; ug-knowledge → knowledge-agent. Inputs: inbox path, archive root, preview/apply mode. Permissions stay on user-authorized paths. Models follow Uliya platform config. Data stays on NAS except platform-supported AI processing.

8. What have you built so far? What is not built yet? What still needs testing on a NAS?

Built: SKILL.md, classification/safety/disclosure references, static-pass package, proposal, local plan simulator. Not built on hardware: live approvals, real OCR quality, tag UX. Needs NAS testing: Downloads resolve, extract schemas, batch moves, verified digest save.

9. How will you test your Skill if you become a Finalist?

Core A: mixed inbox of invoice PDF, contract PDF, screenshot, zip → correct preview categories. Core B: user confirms subset → only those rows move; digest lists leftovers. Edge: empty inbox → report no results and stop without scanning other folders.

10. What are the known limits, risks, or outside dependencies of your Skill?

80-file cap; weak scans may need review; encrypted PDFs stay misc; depends on UGOS experts and platform approvals; no custom executables; India eligibility should be confirmed with organizers if applicable.

Third-party / AI disclosures: UGREEN uliya-skill-kit documentation (required). Skill ZIP is Markdown-only. AI tools: Cursor for authoring/checker iteration; runtime file-agent, document-agent, knowledge-agent on UGOS/Uliya. No embedded credentials or API keys.
